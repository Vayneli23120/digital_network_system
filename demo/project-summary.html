故障单状态机 · Fault State Machine

open 新建 → assigned 已分配 → diagnosing 诊断中 → transferred 已转维修 → resolved 已解决 → closed 已关闭

维修单同步状态：created → repairing → verifying → completed  |  SLA 分级：Critical 4h · Major 24h · Minor 72h · Warning 168h

三种自动创建路径

  • Workflow 规则触发：fault_created 事件 + severity=critical → 自动创建 emergency 维修单
  • AI 分析建议：ADK Agent 分析后 auto_create_maintenance=True → 自动创建维修单
  • 手动转单：运维人员 transfer-to-maintenance → 创建维修单并原子双向关联
  • 去重保护：source_key 机制防止同一事件重复建单；原子事务防并发双重创建

闭环验证机制

  • 维修完成 verify-pass → 故障单自动 resolved
  • maintenance_completed 触发器 → 设备健康分 +10
  • Workflow 自动创建 PM 巡检任务（3 天后）
  • 健康分持续监控 → 低于阈值重新触发告警
  • 管理员 review 机制：自动建单需人工审核，防止误报

设备资产闭环 — 详情 · 备件 · 维修 · 故障一体化

从设备上线到退役的全生命周期追踪，备件序列号级管理，维修-故障-备件三向关联

设备全生命周期

  • 设备档案：SNMP 配置、SSH 凭证组、固件版本、序列号、采购信息、维保到期
  • 健康评分：多因子模型 — 温度 + 故障频率 + 使用年限 + 维修频率 + 日志异常
  • 配置管理：自动备份、变更检测 (diff)、合规扫描、模板部署、配置回滚
  • 端口与流量：接口状态、流量采样、带宽利用率、错误包统计
  • 拓扑关系：LLDP 邻居发现、光纤链路追踪、设备路径计算

备件闭环追踪

  • 序列号级追踪：每个备件独立实例 (SparePartInstance)，从入库到报废全程可查
  • 扫码枪集成：QR 码扫描查询备件全历史 — 哪次维修、装到哪台设备、何时拆下
  • 维修关联：out_to_maintenance FK → 哪个维修单消耗了哪个备件
  • 设备关联：DeviceSpareRelation 记录设备-备件安装位置、操作人、操作时间
  • 库存预警：quantity_in_stock ≤ min_quantity 自动触发低库存告警
  • 报废管理：inuse → pending_scrap → scrapped 完整报废状态机

AI 智能分析引擎 — 集合所有数据，分析研判

Google ADK 多智能体框架 + RAG 知识库 + LiteLLM 多模型路由，让 AI 贯穿运维全流程

🔍 Fault Triage Agent

故障自动分诊：根据设备类型、故障症状、历史案例，判定严重级别与故障类型，推荐处置方案

🔬 Root Cause Agent

根因诊断：综合分析 SNMP 指标、日志、拓扑变更、配置 diff，推断故障根本原因及置信度

📋 Compliance Audit Agent

合规审计：自动检查设备配置是否符合基线模板，标记偏离项，生成整改建议

📈 Health Prediction Agent

健康预测：基于历史故障、性能趋势、设备年限，预测设备健康风险并提前预警

📝 Executive Summary Agent

管理层摘要：自动生成运维周报/月报，提炼关键风险、成本趋势、改进建议

AI 分析能力矩阵

  • 故障 AI 预诊断：Critical/Major 故障创建时自动后台 AI 分析，推断根因与推荐方案
  • AI 自动创建维修单：分析后可选自动创建维修单，直接进入维修流程
  • 故障升级建议：AI 根据事件频率和影响范围，建议升级故障级别
  • RAG 语义检索：pgvector 向量库检索设备手册、SOP 文档、历史故障案例
  • 多模型路由：LiteLLM 统一调度 Kimi / Claude / 本地模型，按任务选择最优模型
  • 运维建议流：Operations 页面 AI 推荐条 — 优先级排序的运维行动建议
